the README ESPConnect row as **board verification** evidence for the N16R8
naming. Do not conflate with product Observation capacity.

## CPU

| Item | Value | Class | Source |
| --- | --- | --- | --- |
| Architecture | Dual-core ESP32-S3, up to 240 MHz capable | hardware capability (doc) | `firmware/esp-ear/README.md` |
| Default CPU frequency in tree `sdkconfig` | 160 MHz; `CONFIG_PM_ENABLE` unset | `configured` in checked-in `firmware/esp-ear/sdkconfig` | `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ=160` |
| Same in `sdkconfig.defaults` | **not set** | discrepancy | `sdkconfig.defaults` has no `CONFIG_ESP_DEFAULT_CPU_FREQ_*` lines |

**Discrepancy:** production intent and diagnostics docs (`docs/diagnostics/ear-l1-perf-optimization.md`)
describe 160 MHz as configured, matching the checked-in `sdkconfig`, but
**`sdkconfig.defaults` does not pin CPU frequency**. Builder “List config” /
fresh `idf.py` flows may depend on IDF defaults unless overlays set it.
Unresolved for Map purposes: whether every catalog build is guaranteed 160 MHz
from defaults alone — cite effective build snapshot when recording performance.
