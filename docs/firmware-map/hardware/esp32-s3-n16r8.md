| Item | Value | Class | Source |

| PSRAM capacity (board) | 8 MB | `measured` / board-verified (ESPConnect), cited in docs | `firmware/esp-ear/README.md` Hardware table (ESP32-S3 QFN56, 8 MB PSRAM AP Memory 3.3 V); comment in `sdkconfig.defaults` |

The Map treats **sdkconfig 16 MB + SPIRAM** as the build `configured` truth and
the README ESPConnect row as **board verification** evidence for the N16R8
naming. Do not conflate with product Observation capacity.

## CPU

| Item | Value | Class | Source |
| --- | --- | --- | --- |
| Architecture | Dual-core ESP32-S3, up to 240 MHz capable | hardware capability (doc) | `firmware/esp-ear/README.md` |
| Product CPU frequency | **240 MHz**; `CONFIG_PM_ENABLE` unset | `configured` | `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240` / `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ=240` in `firmware/esp-ear/sdkconfig.defaults` |
| Product FreeRTOS tick | **100 Hz** | `configured` | `CONFIG_FREERTOS_HZ=100` in same file |
| Runtime diag fields | `cpu_mhz`, `configured_mhz`, `tick_hz` | `source-verified` | `sp_diag_log_resources` → `sp: res …` |

Product catalog / clean `idf.py` builds that apply `sdkconfig.defaults` (no
conflicting overlay; local gitignored `sdkconfig` removed or regenerated) select
240 MHz / 100 Hz. Historical R0 measurement still uses
`sdkconfig.defaults.r0_ref` (160 MHz / 100 Hz). Experimental 1000 Hz tick remains
only in `sdkconfig.defaults.perf_240_1000` — not a product default.
Cite the effective build snapshot when recording performance.
